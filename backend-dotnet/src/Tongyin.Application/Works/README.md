# Works 作品应用层文件分类

本目录按**业务职责/工作流**而不是简单的“接口/实现”分组。所有业务用例仍然属于 `Tongyin.Application.Works` 命名空间；本轮只是文件位置重构，没有变更任何已被 Api、Infrastructure 和测试代码引用的公共类型、方法签名与业务语义。

| 子目录 | 内容 |
| --- | --- |
| `Core/` | 作品创建、查询、列表、选图，以及作品持久化端口和作品快照 |
| `ImageGeneration/` | 图片生成任务登记、队列派发、执行、结果回写和相关端口 |
| `ModelGeneration/` | 3D 模型任务派发、任务认领、GLB 结果回写和相关端口 |
| `Media/` | 原画上传/读取端口和图片大小限制 |
| `Administration/` | 管理后台跨用户作品的只读查询 |
| `Recovery/` | 图片及 3D 模型超时任务的查询、人工核查及审计写入端口 |

**约束：**新功能应优先放入现有职责分组，不要再把所有 `.cs` 文件堆在 `Works/` 根目录；Application 层不能依赖 API/数据库实现。现有的 `Tongyin.Application.Ai` 继续存放 AI 服务商的通用配置及客户端端口，不能随意混入作品生命周期用例。

未来如需进一步细化命名空间，应在单独的兼容性重构中一次性修改跨层引用，并以接口测试确认不影响小程序协议。
